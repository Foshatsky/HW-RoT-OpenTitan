# Практическая работа №1. Разработка UART-сервиса эхо-повтора на Zephyr RTOS

## Техническое задание

Необходимо разработать программный комплекс, состоящий из двух компонентов:

1. **Встраиваемый эхо-сервис**, функционирующий под управлением операционной системы реального времени Zephyr RTOS.

2. **Хост-клиент** — специализированное приложение, запускаемое на рабочей станции и взаимодействующее с сервисом через интерфейс UART.

### Функциональность встраиваемого сервиса

Сервис должен:
- Инициализировать UART через Device Tree (`DT_CHOSEN(zephyr_console)`)
- В бесконечном цикле ожидать поступления байтов из UART (`uart_poll_in`)
- При получении данных немедленно отправлять те же байты обратно (`uart_poll_out`)
- Корректно обрабатывать потоковый ввод без потери данных
- Завершать работу по команде `EXIT`

### Функциональность хост-клиента

Клиент должен:
- Устанавливать соединение с последовательным портом (ttyUSB, PTY)
- Отправлять тестовые данные в сервис
- Принимать эхо-ответ
- Проверять корректность полученных данных (сравнение с отправленными)
- Выводить результат проверки

### Технические требования

| Компонент | Требование |
|-----------|------------|
| Операционная система | Zephyr RTOS |
| Сборочная система | CMake (west build) |
| Язык сервиса | C |
| Язык клиента | C (или Python) |
| Интерфейс | UART |
| Аппаратная абстракция | Device Tree + Zephyr Driver API |
| Целевая платформа | opentitan_earlgrey |

## 1. Цель работы

Данная работа является минимальным, но критически важным шагом для проверки работоспособности всей цепочки взаимодействия:

```
Linux-хост → Verilator → UART → Zephyr-драйвер → Приложение → UART → Verilator → Linux-хост
```

Успешное выполнение подтверждает, что:
- Среда разработки Zephyr настроена корректно (west, SDK, тулчейн)
- Zephyr функционирует на целевой платформе OpenTitan Earlgrey (Verilator)
- UART-драйвер работает и доступен через Device Tree
- Linux может взаимодействовать с симулированным UART через псевдотерминал (PTY)

## 2. Практическая часть

### 2.1. Настройка проекта Zephyr

- Создание структуры проекта: `CMakeLists.txt`, `prj.conf`, `src/main.c`
- `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20.0)
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(echo_service)
target_sources(app PRIVATE src/main.c)
```

- `prj.conf` — для эхо-сервиса дополнительных конфигураций не требуется (минимальная конфигурация Zephyr уже включает UART).

### 2.2. Разработка Zephyr-сервиса

**Ключевые API Zephyr:**

| Функция | Назначение |
|---------|------------|
| `DEVICE_DT_GET(DT_CHOSEN(zephyr_console))` | Получение UART-устройства из Device Tree |
| `device_is_ready(dev)` | Проверка готовности устройства |
| `uart_poll_in(dev, &byte)` | Приём одного байта (polling) |
| `uart_poll_out(dev, byte)` | Отправка одного байта (polling) |
| `printk(...)` | Логгирование в ядре Zephyr |

**Пример сигнатуры main():**

```c
#include <zephyr/kernel.h>
#include <zephyr/drivers/uart.h>
#include <zephyr/device.h>
#include <string.h>

#define DEV_CONSOLE DEVICE_DT_GET(DT_CHOSEN(zephyr_console))

int main(void)
{
    const struct device *dev = DEV_CONSOLE;

    if (!device_is_ready(dev)) {
        printk("UART device not ready!\n");
        return 1;
    }

    printk("=== Echo Service ===\n");
    printk("Send data, service will echo it back. 'EXIT' to stop.\n");

    unsigned char c;
    /* ... цикл приёма и эхо-повтора ... */

    return 0;
}
```

### 2.3. Разработка хост-клиента

- Настройка последовательного порта (termios: 115200 8N1)
- Отправка тестовой строки
- Приём эхо-ответа
- Сравнение отправленных и полученных данных
- Вывод результата проверки (успех/ошибка)

### 2.4. Сборка и запуск

```bash
west build -b opentitan_earlgrey samples/echo_service --pristine -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

Собранный образ запускается на Verilator стандартными средствами OpenTitan. Взаимодействие с UART — через выделенный псевдотерминал (PTY).

## 4. Рекомендации

- Начать с изучения документации Zephyr: [UART Driver API](https://docs.zephyrproject.org/latest/hardware/peripherals/uart.html)
- Для отладки удобно использовать `printk()` — сообщения выводятся в тот же UART
- `uart_poll_in()` возвращает `-1`, если данных нет; это нормально для polling-режима
- В симуляции Verilator UART может терять данные при высокоскоростной передаче — Zephyr-драйвер OpenTitan содержит встроенную обработку таких ситуаций
- Код сервиса должен корректно обрабатывать символ `\r` (carriage return) — некоторые терминалы отправляют его вместо или вместе с `\n`
