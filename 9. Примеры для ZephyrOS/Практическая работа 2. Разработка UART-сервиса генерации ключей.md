# Практическая работа №2. Разработка UART-сервиса генерации и выдачи криптографических ключей на Zephyr RTOS

## Техническое задание

Необходимо разработать программный комплекс, состоящий из двух независимых компонентов:

1. **Встраиваемый криптографический сервис**, функционирующий под управлением операционной системы реального времени Zephyr RTOS.

2. **Хост-клиент** — отдельное приложение, запускаемое на рабочей станции и взаимодействующее с сервисом через интерфейс UART.

### Функциональность встраиваемого сервиса

Сервис должен:
- Инициализировать UART через Device Tree
- Инициализировать криптографическую подсистему (PSA Crypto API)
- Ожидать текстовые команды от хост-клиента
- При получении команды `GENKEY` — формировать новый криптографический ключ AES-256 через `psa_generate_random()`
- При получении команды `STATUS` — возвращать статус готовности
- Возвращать результат в шестнадцатеричном формате с маркерами для автоматического парсинга
- Корректно обрабатывать ошибки с graceful degradation (при недоступности аппаратного RNG — автоматически использовать программный источник энтропии, встроенный в Zephyr)

### Функциональность хост-клиента

Клиент должен:
- Устанавливать соединение с последовательным портом
- Предоставлять интерфейс для отправки команд (интерактивный или пакетный режим)
- Принимать ответы от сервиса
- Извлекать ключ из ответа по маркеру `KEY:`
- Отображать ключ в форматированном виде с указанием:
  - Длины в шестнадцатеричных символах
  - Длины в байтах
  - Соответствующего стандарта (AES-256)

### Технические требования

| Компонент | Требование |
|-----------|------------|
| Операционная система | Zephyr RTOS |
| Криптографический API | PSA Crypto (встроен в Zephyr) |
| Сборочная система | CMake (west build) |
| Язык сервиса | C |
| Язык клиента | C (или Python) |
| Интерфейс | UART |
| Аппаратная абстракция | Device Tree + Zephyr Driver API |
| Целевая платформа | opentitan_earlgrey |

## 2. Практическая часть

### 2.1. Настройка проекта Zephyr

- Создание структуры проекта: `CMakeLists.txt`, `prj.conf`, `src/main.c`
- `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20.0)
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(keygen_service)
target_sources(app PRIVATE src/main.c)
```

- `prj.conf`:

```
CONFIG_PSA_CRYPTO=y
CONFIG_ENTROPY_GENERATOR=y
```

**Пояснение:**
- `CONFIG_PSA_CRYPTO=y` — включает PSA Crypto API (единый интерфейс для всех криптоопераций)
- `CONFIG_ENTROPY_GENERATOR=y` — включает подсистему энтропии

В отличие от подхода с FreeRTOS, где требовалась ручная интеграция mbedTLS (конфигурационный файл, bare-metal заглушки, правила Bazel), здесь достаточно двух строк Kconfig — всё остальное Zephyr делает сам.

### 2.2. Разработка Zephyr-сервиса

**Ключевые API:**

| API | Функция | Назначение |
|-----|---------|------------|
| PSA Crypto | `psa_crypto_init()` | Инициализация криптоподсистемы |
| PSA Crypto | `psa_generate_random(buf, len)` | Генерация криптографически стойких случайных байт |
| UART | `uart_poll_out(dev, byte)` | Отправка байта |
| UART | `uart_poll_in(dev, &byte)` | Приём байта |
| Device | `device_is_ready(dev)` | Проверка готовности устройства |
| Kernel | `printk(...)` | Логгирование |

**Протокол команд:**

| Команда | Ответ | Описание |
|---------|-------|----------|
| `GENKEY` | `KEY:<64 hex-символов>` | Генерация нового AES-256 ключа |
| `STATUS` | `OK:READY` | Проверка готовности сервиса |
| `EXIT` | `OK:BYE` | Корректное завершение |
| (прочее) | `ERR:UNKNOWN_CMD` | Неизвестная команда |

**Структура кода (основные блоки):**
1. Получение UART-устройства через `DEVICE_DT_GET(DT_CHOSEN(zephyr_console))`
2. Инициализация PSA Crypto: `psa_crypto_init()`
3. Бесконечный цикл: чтение строки из UART → обработка команды → отправка ответа
4. Функция `generate_aes256_key()`: вызов `psa_generate_random(key, 32)`
5. Функция `bytes_to_hex()`: преобразование 32 байт → 64 hex-символа

**Обработка ошибок (graceful degradation):**
- В симуляции Verilator аппаратный ENTROPY_SRC может быть недоступен — Zephyr автоматически подключает программный источник через `CONFIG_ENTROPY_GENERATOR=y`
- На реальном железе (FPGA/ASIC) — аппаратный RNG OpenTitan через штатный драйвер
- Переключение происходит на уровне Kconfig, код сервиса не меняется

> **Пример реализации:** полный код сервиса, сборочные файлы и хост-клиент находятся в `crypt_uart/`. Подробное описание каждого шага — в `Пример реализации практической работы №2.md`.

### 2.3. Разработка хост-клиента

- Настройка последовательного порта (termios: 115200 8N1)
- Функция ожидания ответа `READY`
- Отправка команд и чтение ответов
- Парсинг ответа с извлечением ключа по маркеру `KEY:`
- Форматированный вывод ключа с подсчётом длины

Клиент может быть реализован на C (через termios, см. пример в реализации) или Python (через `pyserial`).


## 4. Рекомендации

- **Начать с PSA Crypto:** в Zephyr это штатный API — не нужно интегрировать сторонние библиотеки
- `psa_generate_random()` в симуляции Verilator использует программный источник энтропии; на реальном железе включается аппаратный RNG OpenTitan
- Для отладки UART-взаимодействия рекомендуется сначала реализовать простой эхо-сервис (Практическая работа №1)
- При работе с реальным железом добавить в `prj.conf` драйвер энтропии для конкретного чипа (например, `CONFIG_ENTROPY_NRF5_RNG=y` для Nordic)
- Для автоматического тестирования написать скрипт, отправляющий команды через `socat` или `pyserial`
