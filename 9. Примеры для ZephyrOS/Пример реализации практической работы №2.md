# Пример: Криптографический UART-сервис на Zephyr RTOS с PSA Crypto

## 1. Что имеем в итоге

- **Встраиваемый сервис** под Zephyr RTOS (симуляция или реальное железо): принимает по UART текстовые команды `GENKEY`, `STATUS`, `EXIT`, генерирует через PSA Crypto ключи AES-256 и возвращает их в HEX с маркером `KEY:` и статусными сообщениями.
- **Хост-клиент** на C: подключается к последовательному порту, отправляет команды, принимает и парсит ответ.
- **Сборка**: стандартная система сборки Zephyr (CMake + west / ninja).

Код сервиса находится в `crypt_uart/` — это рабочий проект, готовый к сборке.

## 2. Полная инструкция по реализации

### 2.1. Архитектура проекта

```
crypt_uart/
├── CMakeLists.txt          # Сборочный файл Zephyr
├── prj.conf                # Конфигурация ядра (включение PSA Crypto)
└── src/
    └── main.c              # Код сервиса
```

**Почему именно такая структура:**
- `CMakeLists.txt` — минимальный Zephyr-проект: находит Zephyr SDK, регистрирует приложение, подключает исходники.
- `prj.conf` — включает нужные подсистемы Kconfig: `CONFIG_PSA_CRYPTO=y` (криптография) и `CONFIG_ENTROPY_GENERATOR=y` (источник случайных чисел).
- `src/main.c` — вся логика сервиса в одном файле.

---

### 2.2. Сборочная конфигурация

#### 2.2.1. CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.20.0)
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(keygen_service)
target_sources(app PRIVATE src/main.c)
```

**Что здесь важно:**
- `find_package(Zephyr ...)` — обнаруживает установленный Zephyr SDK.
- `project(keygen_service)` — имя прошивки.
- `target_sources(app PRIVATE ...)` — подключает исходный код к цели `app` (стандартное имя цели в Zephyr).

#### 2.2.2. prj.conf

```
CONFIG_PSA_CRYPTO=y
CONFIG_ENTROPY_GENERATOR=y
```

**Пояснение:**
- `CONFIG_PSA_CRYPTO=y` — включает PSA Crypto API. Это стандартизированный криптографический интерфейс, встроенный в Zephyr через библиотеку TF-M (Trusted Firmware-M) или mbedTLS. Никакой ручной интеграции — всё уже есть.
- `CONFIG_ENTROPY_GENERATOR=y` — включает подсистему энтропии (для симуляции QEMU использует программный источник, для реального железа — аппаратный).

> **Сравнительный анализ — Сложность интеграции:** В отличие от подхода с FreeRTOS + mbedTLS + Bazel, где приходилось вручную интегрировать библиотеку, писать bare-metal заглушки и настраивать Bazel-правила, здесь PSA Crypto — штатная подсистема Zephyr, включаемая двумя строками в Kconfig. Никаких заглушек, никаких проблем с линковкой.

### 2.3. Код сервиса

**Файл:** `crypt_uart/src/main.c`

#### 2.3.1. Заголовки и константы

```c
#include <zephyr/kernel.h>
#include <zephyr/drivers/uart.h>
#include <zephyr/device.h>
#include <string.h>
#include <psa/crypto.h>

#define DEV_CONSOLE  DEVICE_DT_GET(DT_CHOSEN(zephyr_console))
#define CMD_BUF_SIZE 64
#define AES256_KEY_BYTES 32  /* 256 бит = 32 байта */
```

**Ключевые моменты:**
- `<psa/crypto.h>` — PSA Crypto API, единый интерфейс для всех криптоопераций.
- `DEVICE_DT_GET(DT_CHOSEN(zephyr_console))` — получение UART-устройства из Device Tree. Не нужно знать физический адрес или номер порта — Zephyr сам подставит нужное устройство для текущей платформы.
- `AES256_KEY_BYTES = 32` — длина ключа AES-256 в байтах.

#### 2.3.2. UART-функции

```c
/* Отправить строку побайтово через UART */
static void uart_send_string(const struct device *dev, const char *str)
{
    while (*str) {
        uart_poll_out(dev, *str++);
    }
}

/* Прочитать строку из UART до '\n' или переполнения буфера.
 * Возвращает длину прочитанной строки (без '\n').
 * '\n' заменяется на '\0'. */
static int uart_read_line(const struct device *dev, char *buf, int max_len)
{
    int pos = 0;
    unsigned char c;
    while (pos < max_len - 1) {
        if (uart_poll_in(dev, &c) == 0) {
            if (c == '\n' || c == '\r') break;
            buf[pos++] = (char)c;
        }
    }
    buf[pos] = '\0';
    return pos;
}
```

**Особенности Zephyr UART API:**
- `uart_poll_out(dev, byte)` — посимвольная отправка в режиме polling. Простой и надёжный способ без прерываний и DMA.
- `uart_poll_in(dev, &c)` — посимвольный приём. Возвращает 0 при успехе.
- В отличие от OpenTitan DIF, не нужно вручную манипулировать регистрами через mmio — Zephyr-драйвер абстрагирует железо.

#### 2.3.3. Криптографические функции

```c
/* Инициализация PSA Crypto */
static int crypto_init(void)
{
    psa_status_t status = psa_crypto_init();
    if (status != PSA_SUCCESS) {
        printk("psa_crypto_init() failed: %d\n", status);
        return -1;
    }
    printk("PSA Crypto initialized.\n");
    return 0;
}

/* Генерация случайных 32 байт (AES-256 ключ) через PSA RNG */
static int generate_aes256_key(uint8_t *key_buf)
{
    psa_status_t status = psa_generate_random(key_buf, AES256_KEY_BYTES);
    if (status != PSA_SUCCESS) {
        printk("psa_generate_random() failed: %d\n", status);
        return -1;
    }
    return 0;
}

/* Преобразование массива байт в hex-строку */
static void bytes_to_hex(const uint8_t *src, int src_len,
                         char *dst, int dst_len)
{
    static const char hex_chars[] = "0123456789ABCDEF";
    int i;
    for (i = 0; i < src_len && (i * 2 + 1) < dst_len - 1; i++) {
        dst[i * 2]     = hex_chars[(src[i] >> 4) & 0x0F];
        dst[i * 2 + 1] = hex_chars[src[i] & 0x0F];
    }
    dst[i * 2] = '\0';
}
```

**Почему PSA Crypto:**
- `psa_crypto_init()` — единая точка инициализации всей криптоподсистемы.
- `psa_generate_random()` — аппаратно-независимая генерация случайных чисел. На QEMU использует программный энтропийный источник, на реальном железе — аппаратный RNG.
- Никаких ручных контекстов (`mbedtls_ctr_drbg_context`), никакой ручной регистрации источников энтропии — PSA API берёт это на себя.

> **Сравнительный анализ — Потребление памяти:** PSA Crypto в Zephyr использует mbedTLS под капотом, но благодаря интеграции на уровне Kconfig, в прошивку попадают только нужные модули. Не нужно писать `exclude`-списки или править `config.h` — Kconfig сам отключает неиспользуемые модули.

#### 2.3.4. Обработчик команд

```c
static void handle_command(const struct device *dev, const char *cmd)
{
    if (strcmp(cmd, "GENKEY") == 0) {
        uint8_t key[AES256_KEY_BYTES];
        char hex[AES256_KEY_BYTES * 2 + 1];
        if (generate_aes256_key(key) == 0) {
            bytes_to_hex(key, AES256_KEY_BYTES, hex, sizeof(hex));
            uart_send_string(dev, "KEY:");
            uart_send_string(dev, hex);
            uart_send_string(dev, "\n");
        } else {
            uart_send_string(dev, "ERR:KEYGEN_FAIL\n");
        }
    } else if (strcmp(cmd, "STATUS") == 0) {
        uart_send_string(dev, "OK:READY\n");
    } else if (strcmp(cmd, "EXIT") == 0) {
        uart_send_string(dev, "OK:BYE\n");
    } else {
        uart_send_string(dev, "ERR:UNKNOWN_CMD\n");
    }
}
```

**Протокол команд:**

| Команда | Ответ | Описание |
|---------|-------|----------|
| `GENKEY` | `KEY:<64 hex-символов>` | Генерация нового AES-256 ключа |
| `STATUS` | `OK:READY` | Проверка готовности сервиса |
| `EXIT` | `OK:BYE` | Корректное завершение |
| (прочее) | `ERR:UNKNOWN_CMD` | Неизвестная команда |

**Принципы протокола:**
- Текстовые команды — удобно тестировать через любой терминал (screen, minicom, picocom).
- Жёсткие маркеры (`KEY:`, `OK:`, `ERR:`) — однозначный парсинг на стороне клиента.
- Команда завершается переводом строки (`\n`).

#### 2.3.5. Точка входа

```c
int main(void)
{
    const struct device *dev = DEV_CONSOLE;
    printk("=== AES-256 Key Generation Service ===\n");

    if (!device_is_ready(dev)) {
        printk("UART device not ready!\n");
        return 1;
    }
    printk("UART ready.\n");

    if (crypto_init() != 0) return 1;

    uart_send_string(dev, "READY\n");

    char cmd_buf[CMD_BUF_SIZE];
    while (1) {
        int len = uart_read_line(dev, cmd_buf, sizeof(cmd_buf));
        if (len > 0) {
            handle_command(dev, cmd_buf);
            if (strcmp(cmd_buf, "EXIT") == 0) break;
        }
    }
    printk("Service stopped.\n");
    return 0;
}
```

**Особенности:**
- `device_is_ready(dev)` — стандартная проверка готовности устройства в Zephyr.
- `printk()` — логгирование в ядре Zephyr (аналог `printf`, но легковесный и не требующий libc).
- Бесконечный цикл опроса UART — характерный паттерн для RTOS без вытеснения на уровне main-потока.

### 2.5. Хост-клиент

#### 2.5.1. Код клиента

Клиент подключается к последовательному порту, отправляет команды и парсит ответ.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <termios.h>
#include <errno.h>

#define BUFFER_SIZE 4096

static int open_serial(const char *device) {
    int fd = open(device, O_RDWR | O_NOCTTY | O_SYNC);
    if (fd < 0) { perror("open"); return -1; }

    struct termios tty;
    memset(&tty, 0, sizeof(tty));
    tcgetattr(fd, &tty);

    cfsetospeed(&tty, B115200);
    cfsetispeed(&tty, B115200);
    tty.c_cflag |= (CLOCAL | CREAD);
    tty.c_cflag &= ~CSIZE; tty.c_cflag |= CS8;
    tty.c_cflag &= ~PARENB;
    tty.c_cflag &= ~CSTOPB;
    tty.c_cflag &= ~CRTSCTS;
    tty.c_lflag &= ~(ICANON | ECHO | ECHOE | ISIG);
    tty.c_iflag &= ~(IXON | IXOFF | IXANY);
    tty.c_oflag &= ~OPOST;
    tty.c_cc[VMIN] = 0;
    tty.c_cc[VTIME] = 5;
    tcsetattr(fd, TCSANOW, &tty);
    return fd;
}

static int send_command(int fd, const char *cmd) {
    char buf[BUFFER_SIZE] = {0};
    char full_cmd[256];
    snprintf(full_cmd, sizeof(full_cmd), "%s\n", cmd);
    write(fd, full_cmd, strlen(full_cmd));

    /* Приём ответа */
    int total = 0;
    usleep(200000);  /* 200ms на ответ */
    int n = read(fd, buf, BUFFER_SIZE - 1);
    if (n > 0) {
        buf[n] = '\0';
        printf("Response: %s", buf);
    }
    return 0;
}

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <serial_port> [command]\n", argv[0]);
        fprintf(stderr, "  serial_port: /dev/ttyUSB0, /dev/pts/N, etc.\n");
        fprintf(stderr, "  command: GENKEY, STATUS, EXIT (default: interactive)\n");
        return 1;
    }

    int fd = open_serial(argv[1]);
    if (fd < 0) return 1;

    if (argc >= 3) {
        send_command(fd, argv[2]);
    } else {
        printf("Interactive mode. Commands: GENKEY, STATUS, EXIT, QUIT\n");
        char line[256];
        while (1) {
            printf("> ");
            if (!fgets(line, sizeof(line), stdin)) break;
            line[strcspn(line, "\n")] = '\0';
            if (strcmp(line, "QUIT") == 0) break;
            send_command(fd, line);
        }
    }

    close(fd);
    return 0;
}
```

#### 2.5.2. Компиляция и использование

```bash
gcc -o uart_client uart_client.c

# Примеры запуска:
./uart_client /dev/pts/X              # интерактивный режим
./uart_client --no-wait /dev/pts/X 1  # одна команда без ожидания
./uart_client -v /dev/pts/X           # подробный вывод
```

## 3. Особенности реализации на Zephyr

### 3.1. Преимущества перед FreeRTOS/Bazel-подходом

| Аспект | FreeRTOS + OpenTitan + Bazel | Zephyr RTOS |
|--------|------------------------------|-------------|
| **Криптография** | Ручная интеграция mbedTLS: правила Bazel, конфиг, заглушки | `CONFIG_PSA_CRYPTO=y` — одна строка в `prj.conf` |
| **Сборка** | Bazel — сложная настройка, специфична для OpenTitan | CMake — стандарт индустрии, единый для всех платформ |
| **Аппаратная абстракция** | OpenTitan DIF — привязан к конкретному чипу | Device Tree + Zephyr Drivers — переносимый код |
| **Стандартная библиотека** | Заглушки для bare-metal | Полная поддержка newlib/picolibc |
| **Переносимость** | Только OpenTitan (Verilator / FPGA / ASIC) | QEMU, десятки реальных плат |

### 3.2. Программный источник энтропии

В симуляции Verilator аппаратный источник энтропии OpenTitan (ENTROPY_SRC/CSRNG) может быть недоступен или требовать сложной дополнительной настройки. Zephyr решает эту проблему на уровне Kconfig — через `CONFIG_ENTROPY_GENERATOR=y` автоматически подключается программный источник энтропии. При переносе на реальное железо (FPGA / ASIC) достаточно включить драйвер аппаратного ENTROPY_SRC — код сервиса не меняется.

Это демонстрирует принцип graceful degradation: система работает на базовом уровне даже при недоступности аппаратной энтропии.

### 3.3. Особенности UART на OpenTitan

Виртуальный UART в Verilator может страдать от потери данных при высокоскоростной передаче — симулятор не всегда успевает обработать поток. В отличие от FreeRTOS-реализации (где вручную добавлены `busy-loop` задержки), Zephyr-драйвер UART для OpenTitan уже содержит встроенную обработку таких ситуаций на уровне драйвера.
