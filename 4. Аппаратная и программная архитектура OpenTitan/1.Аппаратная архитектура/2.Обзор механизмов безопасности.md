# Обзор механизмов безопасности на аппаратном уровне
В проекте OpenTitan используется ряд подходов проектирования аппаратного обеспечения, повышающих устойчивость системы к атакам. 


## Разряженная кодировка состояний конечных автоматов (sparse FSM encoding)
Во всех конечных автоматах состояния кодируются специальным образом, с помощью скрипта *./util/design/sparse-fs-encode.py* Этот скрипт обеспечивает заданное минимальное расстояние Хэмминга между соседними состояниями автомата. Например, в файле *flash_ctrl_arb.sv* состояния генерируются следующим образом:
```
  // arbitration FSM
  // Encoding generated with:
  // $ ./util/design/sparse-fsm-encode.py -d 5 -m 5 -n 10 \
  //      -s 1044018132 --language=sv --avoid-zero
  //
  // Hamming distance histogram:
  //
  //  0: --
  //  1: --
  //  2: --
  //  3: --
  //  4: --
  //  5: |||||||||||||||||||| (50.00%)
  //  6: |||||||||||||||| (40.00%)
  //  7: |||| (10.00%)
  //  8: --
  //  9: --
  // 10: --
  //
  // Minimum Hamming distance: 5
  // Maximum Hamming distance: 7
  // Minimum Hamming weight: 5
  // Maximum Hamming weight: 7
  //
  localparam int StateWidth = 10;
  typedef enum logic [StateWidth-1:0] {
    StReset    = 10'b0011010110,
    StHw       = 10'b1111101110,
    StSwActive = 10'b1100101001,
    StSwIdle   = 10'b1000000010,
    StDisabled = 10'b0100010101
  } arb_state_e;
```

Такая кодировка состояний конечного автомата значительно более устойчива к помехам, чем классические кодировки, используемые при проектировании конечных автоматов. В случае возникновения состояния, не заданного в таблице, автомат переходит в состояние ошибки и сигнализирует об этом вышестоящим уровням:

```
      default: begin
        fsm_err_o = 1'b1;
      end
```

## Многобитные кодировки единичного и нулевого состояния (mubi)
Во многих местах в проекте используется многобитная кодировка единичного и нулевого состояний. Определены кодировки состояний с длиной слова от 4-х до 32-х бит. Наиболее употребительная - mubi4_t, определена в *prim_mubi_pkg.sv*:
```
  parameter int MuBi4Width = 4;
  typedef enum logic [MuBi4Width-1:0] {
    MuBi4True = 4'h6, // enabled
    MuBi4False = 4'h9  // disabled
  } mubi4_t;

```
Как видно, из множества 16-ти значений определены только два - True и False. Все остальные значения интерпретируются как неопределенные. Такая кодировка более устойчива к помехам по сравнению с однобитной кодировкой состояний нуля и единицы.
  
## Кодировка состояний жизненного цикла устройства
В проекте применяется специальная кодировка состояний жизненного цикла устойства, а также ряда параметров контроллера жизненного цикла (lc_ctrl), таких как счетчик перехода состояний, указатель на состояние отладки, владение, авторизация. Состояния генерируются с помощью скрипта *./util/design/gen-lc-state-enc.py*
В файле lc_ctrl_state_pkg.sv генерируется набор параметров:
```
  // The A/B values are used for the encoded LC state.
  parameter logic [15:0] A0 = 16'b1000110001100000; // ECC: 6'b101010
  parameter logic [15:0] B0 = 16'b1011110111101110; // ECC: 6'b101110

  parameter logic [15:0] A1 = 16'b0001010001100010; // ECC: 6'b011001
  parameter logic [15:0] B1 = 16'b1101010111100110; // ECC: 6'b111111
```
...
```
  // The I/J values are used for the encoded AUTH state.
  parameter logic [15:0] I0 = 16'b0101110110010000; // ECC: 6'b010000
  parameter logic [15:0] J0 = 16'b1111110111010010; // ECC: 6'b111000

  parameter logic [15:0] I1 = 16'b0000010001001111; // ECC: 6'b000011
```
