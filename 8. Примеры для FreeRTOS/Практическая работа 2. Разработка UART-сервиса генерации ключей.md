# Практическая работа №2. Разработка UART-сервиса генерации и выдачи криптографических ключей на платформе OpenTitan + FreeRTOS

## Техническое задание

Необходимо разработать программный комплекс, состоящий из двух независимых компонентов:

1. **Встраиваемый криптографический сервис**, функционирующий под управлением операционной системы реального времени FreeRTOS на платформе OpenTitan (в симуляции Verilator).

2. **Хост-клиент** - отдельное приложение, запускаемое на рабочей станции и взаимодействующее с сервисом через интерфейс UART.

### Функциональность встраиваемого сервиса

Сервис должен:
- Инициализировать UART для приёма команд и отправки ответов
- Интегрировать и инициализировать выбранную криптографическую библиотеку
- Ожидать команды от хост-клиента
- При получении команды генерации - формировать новый криптографический ключ средствами библиотеки
- При получении команды выдачи - отправлять текущий ключ
- Возвращать результат в шестнадцатеричном формате с чёткими маркерами для автоматического парсинга
- Корректно обрабатывать ошибки с возможностью graceful degradation (принцип проектирования систем, при котором приложение продолжает функционировать на базовом уровне, даже если часть его компонентов выходит из строя, устарела или недоступна)

### Функциональность хост-клиента

Клиент должен:
- Устанавливать соединение с симулированным UART (псевдотерминал PTY)
- Предоставлять интерфейс для отправки команд (интерактивный или пакетный режим)
- Принимать ответы от сервиса
- Извлекать ключ из ответа по маркерам
- Отображать ключ в форматированном виде с указанием:
  - Длины в шестнадцатеричных символах
  - Длины в байтах
  - Соответствующего стандарта (например, AES-256)

### Технические требования

| Компонент | Требование |
|-----------|------------|
| Платформа | OpenTitan Earlgrey |
| Симуляция | Verilator |
| Операционная система | FreeRTOS |
| Сборочная система | Bazel |
| Язык сервиса | C |
| Язык клиента | C |
| Интерфейс | UART |

## 1. Исследовательская часть

Перед практической реализацией требуется провести аналитическую работу по выбору криптографической библиотеки.

### Направления исследования

**1.1. Обзор доступных решений**
- Какие криптографические библиотеки существуют для встраиваемых систем?
- Какие из них имеют официальную поддержку FreeRTOS или успешные порты?
- Какие библиотеки уже присутствуют в экосистеме OpenTitan?

**1.2. Поддержка отечественных стандартов (ГОСТ)**
- Присутствует ли поддержка российских криптостандартов в открытых версиях?
- Если да - в каком объёме и на каких лицензионных условиях?
- Существуют ли сторонние реализации или патчи, добавляющие ГОСТ?

**1.3. Особенности интеграции в bare-metal окружение**
- Какие системные зависимости имеются у рассматриваемых библиотек?
- Насколько сложна адаптация к архитектуре RISC-V без стандартной библиотеки C?
- Какие модули необходимо отключить для функционирования в условиях ограниченных ресурсов?

**1.4. Сравнительный анализ**
Сравнить отобранные библиотеки по критериям:
- Потребление памяти (Flash/RAM)
- Сложность интеграции в Bazel
- Качество и полнота документации

**Результат исследования:** краткий отчёт (1-2 страницы) с обоснованным выбором библиотеки либо с аргументированным объяснением невозможности реализации с использованием ГОСТ.

## 2. Практическая часть

### 2.1. Интеграция выбранной библиотеки
- Добавление исходных текстов библиотеки в проект OpenTitan
- Написание правил сборки для Bazel
- Конфигурирование библиотеки для bare-metal (отключение файловой системы, сетевых функций, динамической памяти и т.д.)
- Исключение модулей, требующих POSIX-окружения

### 2.2. Разработка FreeRTOS-сервиса
- Инициализация UART через Device Interface Functions (DIF)
- Инициализация выбранной криптографической библиотеки (контексты, настройка источников энтропии)
- Реализация цикла приёма и обработки команд
- Генерация ключей требуемой длины с использованием API библиотеки
- Форматированный вывод с маркерами, позволяющими однозначно извлечь ключ на стороне клиента
- Обработка ошибок с fallback-стратегией при сбоях инициализации или генерации

### 2.3. Разработка хост-клиента
- Настройка последовательного порта (termios для C / pyserial для Python)
- Реализация функции ожидания готовности сервиса
- Отправка команд и чтение ответов
- Парсинг ответа с извлечением ключа по маркерам
- Форматированный вывод ключа с подсчётом длины

## 3. Рекомендации

- Начать с анализа штатной криптографической библиотеки OpenTitan (cryptolib) - она уже интегрирована в экосистему и не требует дополнительной настройки сборки
- Для отладки UART-взаимодействия рекомендуется сначала реализовать простой эхо-сервис и убедиться в корректности приёма/передачи данных

**Важно:** в условиях симуляции Verilator аппаратный источник энтропии OpenTitan (ENTROPY_SRC/CSRNG) может быть недоступен или требовать сложной дополнительной настройки. В связи с этим допустимо и рекомендуется:
  - Использовать программный источник энтропии (fake entropy source) для демонстрации работоспособности криптографической подсистемы
  - Либо реализовать graceful degradation - при неудачной инициализации аппаратного RNG автоматически переключаться на программную генерацию

Данный компромисс следует явно отразить в исследовательском отчёте с пояснением, что в реальном аппаратном OpenTitan проблема решается штатными средствами
