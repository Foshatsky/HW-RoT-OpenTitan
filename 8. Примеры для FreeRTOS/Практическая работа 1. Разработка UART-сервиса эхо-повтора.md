# Практическая работа №1. Разработка UART-сервиса эхо-повтора на платформе OpenTitan + FreeRTOS

## Техническое задание

Необходимо разработать программный комплекс, состоящий из двух компонентов:

1. **Встраиваемый эхо-сервис**, функционирующий под управлением операционной системы реального времени FreeRTOS на платформе OpenTitan (в симуляции Verilator).

2. **Хост-клиент** - специализированное приложение, запускаемое на рабочей станции и взаимодействующее с сервисом через интерфейс UART.

### Функциональность встраиваемого сервиса

Сервис должен:
- Инициализировать UART для приёма и отправки данных
- В бесконечном цикле ожидать поступления байтов из UART
- При получении данных немедленно отправлять те же байты обратно (эхо-повтор)
- Корректно обрабатывать потоковый ввод без потери данных

### Функциональность хост-клиента

Клиент должен:
- Устанавливать соединение с симулированным UART (псевдотерминал PTY)
- Отправлять тестовые данные в сервис
- Принимать эхо-ответ
- Проверять корректность полученных данных (сравнение с отправленными)
- Выводить результат проверки

### Технические требования

| Компонент | Требование |
|-----------|------------|
| Платформа | OpenTitan Earlgrey |
| Симуляция | Verilator |
| Операционная система | FreeRTOS |
| Сборочная система | Bazel |
| Язык сервиса | C |
| Язык клиента | C |
| Интерфейс | UART |

## 1. Цель работы

Данная работа является минимальным, но критически важным шагом для проверки работоспособности всей цепочки взаимодействия:

```
Linux-хост → Verilator → UART → FreeRTOS-драйвер → Приложение → UART → Verilator → Linux-хост
```

Успешное выполнение подтверждает, что:
- Среда разработки и сборки OpenTitan настроена корректно
- FreeRTOS функционирует на симулируемой платформе
- UART-драйвер работает и доступен из пользовательского приложения
- Linux может взаимодействовать с Verilator через псевдотерминал как с обычным TTY-устройством

---

## 2. Практическая часть

### 2.1. Разработка FreeRTOS-сервиса
- Инициализация UART через Device Interface Functions (DIF)
- Создание задачи FreeRTOS для обработки UART
- Реализация цикла приёма данных
- Немедленная отправка полученных байтов обратно
- Обработка ошибок приёма/передачи

### 2.2. Разработка хост-клиента
- Настройка последовательного порта
- Отправка тестовых данных
- Приём эхо-ответа
- Сравнение отправленных и полученных данных
- Вывод результата проверки (успех/ошибка)

### 2.3. Сборка и запуск
- Добавление цели сборки в Bazel
- Запуск симуляции Verilator
- Подключение клиента к выделенному псевдотерминалу (PTY)
