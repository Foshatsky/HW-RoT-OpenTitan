### МЕТОД: Временная симуляция на уровне вентилей (Gate-Level Timing Simulation)
### КАТЕГОРИЯ: 4. Верификация на уровне вентилей
### ФОРМАЛЬНОСТЬ: неформальный

### СУТЬ МЕТОДА:
Временная симуляция (timing simulation) — это метод верификации цифровых схем, при котором симулятор учитывает задержки распространения сигналов через логические элементы и межсоединения. В отличие от функциональной (RTL) симуляции, где предполагается, что все сигналы переключаются мгновенно (delta-циклы), временная симуляция использует информацию о задержках — либо встроенных в Verilog-модели через конструкции `#delay`, либо переданных через Standard Delay Format (SDF) — для проверки корректности работы схемы с учётом реальных временных характеристик.

Основная идея метода: смоделировать поведение схемы после синтеза (gate-level netlist), где каждый вентиль имеет определённую задержку. Это позволяет выявить ошибки, связанные с нарушением временных ограничений (setup/hold time), гонками сигналов (race conditions), состязаниями (hazards) и нестабильностью выходов до завершения переходных процессов. Временная симуляция особенно важна для схем с комбинационными задержками, когда выход может быть некорректен до истечения задержки (X-состояния), и необходимо убедиться, что данные успевают захватываться триггерами на следующем такте.

### ИСТОРИЧЕСКАЯ СПРАВКА:
Timing simulation применяется с 1970-х годов, когда появились первые симуляторы логических схем на уровне вентилей (HILO, Tegas, Silos). Verilog (1984, Gateway Design Automation) с самого начала поддерживал задержки через `#delay`. В 1990-х индустрия перешла к SDF (Standard Delay Format, OVI 1995, IEEE 1497-1999), позволяющему разделять функциональное описание от временных характеристик. [Icarus Verilog](../tools_instructions/iverilog.md) (2001, Stephen Williams) поддерживает `#delay` для behavioural-моделей и частично SDF. Современные промышленные симуляторы (Synopsys VCS, Cadence Xcelium, Siemens Questa) имеют полную поддержку SDF-аннотации для gate-level netlist.

### ПОДРОБНОЕ ОПИСАНИЕ МЕТОДА И ЭКСПЕРИМЕНТА:
Ниже приведен практический пример, в котором реализован сумматор с комбинационной задержкой 5 нс (моделируется через `#5` в always-блоке). Тестбенч подаёт входные значения и проверяет, что выход содержит X (неопределённость) до истечения задержки и корректное значение после. Хотя данная модель упрощена (задержка не зависит от направления перехода и нагрузки), она иллюстрирует принцип: без учёта задержек корректность схемы может быть не гарантирована. В промышленности вместо inline `#delay` используется SDF-аннотация, генерируемая инструментами статического временного анализа (STA) после размещения и трассировки (place & route).

Модуль delayed_adder (delayed_adder.v) реализует 4-битный сумматор, у которого вычисление суммы происходит с задержкой 5 нс:
```
always @(*) begin
    #5 sum = a + b;
end
```

Тестбенч последовательно подает три пары значений (0+0, 5+3, 9+7) с интервалом #6, чтобы выход успел стабилизироваться. Четвертый тест проверяет значение сразу через 1 нс (до истечения задержки — сумма должна быть X или предыдущим значением 16), а затем через 5 нс, когда сумма должна стать корректной (6). VCD-дамп открывается для просмотра временных диаграмм.

В промышленности вместо `#5` используется SDF-файл, сгенерированный после статического временного анализа (PrimeTime, Tempus). SDF содержит точные значения задержек распространения для каждого логического элемента и межсоединения, с учётом температуры, напряжения и производственных разбросов (PVT: process, voltage, temperature). SDF-аннотация загружается через системную задачу `$sdf_annotate()`.

### ЛИСТИНГИ (код, скрипты):

**Код тестбенча на Verilog:**
```systemverilog
`timescale 1ns/1ps

module tb_delays;
   reg [3:0] a, b;
   wire [4:0] sum;

   delayed_adder dut(.*);

   initial begin
       $dumpfile("test_timing.vcd");
       $dumpvars(0, tb_delays);

       $display("Time=%0t  a=0  b=0  sum=%d", $time, sum);
       a = 4'd0; b = 4'd0;
       #6;
       $display("Time=%0t  a=0  b=0  sum=%d (expected 0)", $time, sum);

       a = 4'd5; b = 4'd3;
       #6;
       $display("Time=%0t  a=5  b=3  sum=%d (expected 8)", $time, sum);

       a = 4'd9; b = 4'd7;
       #6;
       $display("Time=%0t  a=9  b=7  sum=%d (expected 16)", $time, sum);

       a = 4'd2; b = 4'd4;
       #1;
       $display("Time=%0t  a=2  b=4  sum=%d (expected 6 before delay)", $time, sum);
       #5;
       $display("Time=%0t  a=2  b=4  sum=%d (expected 6 after delay)", $time, sum);

       $finish;
   end
endmodule
```

### АНАЛИЗ РЕЗУЛЬТАТОВ:
Вывод симуляции наглядно демонстрирует поведение временной задержки:
- Time=0: sum = X (неопределённость). Входы a=0, b=0 поданы, но задержка 5 нс ещё не прошла — сумма ещё не вычислена.
- Time=6000 (6 нс): sum = 0 (корректно, после задержки). После смены входов на 5+3 — снова X до завершения задержки.
- Time=12000: sum = 8 (5+3, корректно через 6 нс).
- Time=18000: sum = 16 (9+7, корректно).
- Time=19000: a=2,b=4 поданы, но прошло лишь 1 нс — выход всё ещё показывает предыдущее значение 16 (остатки от предыдущего вычисления), а не 6. Это важный эффект: до завершения задержки на выходе может быть мусор (X или предыдущее значение).
- Time=24000: sum = 6 (через 5 нс после установки входов) — корректное значение.

Этот пример демонстрирует, что при симуляции без учёта задержек (RTL-simulation) подобные переходные состояния не видны, и некорректное чтение данных до завершения задержки может остаться незамеченным.

### ВЫВОД ПО МЕТОДУ:
Timing simulation на уровне вентилей является критическим этапом верификации для любых микропроцессоров и ASIC. Без неё ошибки, связанные с задержками (нарушение setup/hold, гонки, hazards), могут проявиться только на кремнии, что приводит к дорогостоящим перевыпускам маски (mask re-spin). Метод неформальный (проверяет лишь конечные наборы векторов), но при правильно построенных тестовых сценариях позволяет выявить большинство временных проблем. Сложность реализации средняя: для промышленной SDF-симуляции требуется наличие gate-level netlist, библиотеки стандартных ячеек (Liberty), STA-инструментов и лицензированного симулятора (VCS, Xcelium, Questa). Для open-source исследовательских проектов (например, OpenROAD) существует поддержка SDF-симуляции через [Icarus Verilog](../tools_instructions/iverilog.md) с SDF-аннотацией (опционально), но её функциональность ограничена.
