### МЕТОД: Формальная проверка эквивалентности (Equivalence Checking, EC)
### КАТЕГОРИЯ: 3. Микроархитектурная и RTL-верификация / Формальная
### ФОРМАЛЬНОСТЬ: формальный

### СУТЬ МЕТОДА:
Формальная проверка эквивалентности (Equivalence Checking) — это метод математического доказательства того, что две модели цифровой схемы реализуют одну и ту же логическую функцию. В контексте верификации процессоров это чаще всего означает сравнение двух RTL-описаний: эталонного (reference, gold model) и имплементации (implementation). Если для всех возможных входных комбинаций обе модели дают идентичные выходные сигналы, они считаются эквивалентными. Метод является формальным, то есть обеспечивает 100% покрытие входного пространства без необходимости симуляции.

Основная идея заключается в построении так называемой «miter-схемы» (miter circuit): два сравниваемых модуля подключаются к общим входам, а их выходы подаются на элемент XOR (сравнение). Выход XOR считается утверждением (assert), которое должно быть всегда ложно (нуль), пока модули эквивалентны. Затем эта схема передаётся SAT-решателю. Если решатель находит такой набор входных значений, при котором выходы различаются (XOR = 1), фиксируется ошибка и выдаётся контрпример. Если решатель доказывает, что такой набор невозможен, эквивалентность подтверждена.

В приведенном ниже практическом примере сравниваются две реализации 4-битного сумматора: поведенческая (ref_add — `assign sum = a + b`) и структурная (impl_add — ripple-carry сумматор на полных сумматорах). Формальная проверка проведена через [Yosys](../../tools_instructions/yosys.md) с командами `miter` и `sat`. Yosys — это открытый фреймворк для синтеза цифровых схем: он преобразует описания на Verilog в логические сети (netlist), поддерживает формальную верификацию (проверку эквивалентности, bounded model checking, FPV) и является основой многих open-source инструментов для проектирования и верификации RTL.

Был написан скрипт, который выполняет следующие операции в Yosys:
1. `read_verilog ref.v` — загрузка эталонного модуля ref_add (поведенческий).
2. `rename ref_add ref` — переименование для корректного сопоставления.
3. `read_verilog impl.v` — загрузка модуля имплементации impl_add (структурный ripple-carry).
4. `rename impl_add impl` — переименование.
5. `miter -equiv -flatten ref impl miter` — построение miter-схемы: общие входы a[3:0], b[3:0], выходы ref.sum[4:0] и impl.sum[4:0] подаются на XOR. Флаг `-flatten` сворачивает иерархию.
6. `sat -verify -prove-asserts miter` — SAT-решатель пытается найти контрпример, при котором assert из miter нарушается.

Здесь используется 4-битный сумматор на Verilog, который сравнивается с аналогичным сумматором, реализованным не через встроенную операцию "+", а вручную с использованием четырёх полных сумматоров, соединённых по схеме ripple-carry (реализация корректна).

### ИСТОРИЧЕСКАЯ СПРАВКА:
Equivalence checking как промышленный метод появился в середине 1990-х годов, когда компания Chrysalis (позже Avant!, Synopsys) выпустила инструмент FormalCheck (Design VERIFYer). В 2000-х Synopsys Formality стал стандартом де-факто для формальной верификации эквивалентности RTL-to-gate и gate-to-gate. Yosys (начало 2010-х) добавил поддержку miter-based equivalence checking через SAT, сделав метод доступным в open-source. Ключевые теоретические работы: Brand, D. "Verification of large synthesized designs" (1993); Kuehlmann, A. et al. "Robust Boolean reasoning for equivalence checking and functional property verification" (2002).

### АНАЛИЗ РЕЗУЛЬТАТОВ:
Успешное завершение формально доказывает, что выходы ref_add и impl_add идентичны для всех 2^8 = 256 возможных комбинаций входов a и b. Ripple-carry сумматор на полных сумматорах функционально эквивалентен поведенческому `assign sum = a + b`. Никаких расхождений не обнаружено. Данный метод работает для комбинационных схем любой сложности — главное, чтобы сравнение было корректно построено с точки зрения соответствия портов.

### ВЫВОД ПО МЕТОДУ:
Equivalence Checking — незаменимый метод в маршруте проектирования процессоров, особенно при верификации RTL-to-RTL (рефакторинг, замена микроархитектуры) и RTL-to-gate (проверка корректности синтеза). Метод формально строг (100% покрытие входного пространства) и не требует написания тестов. Сложность реализации для модуля с несколькими тысячами логических элементов невысока — достаточно двух Verilog-файлов и вызова Yosys. Для целых процессорных ядер (миллионы элементов) используются коммерческие инструменты (Synopsys Formality, Cadence Conformal, OneSpin 360 EC).
