# Подключение к UART через screen

### Что такое screen?

`screen` — терминальный мультиплексор GNU, который помимо управления
сессиями умеет работать с последовательными портами. В контексте данного
проекта `screen` используется для интерактивного подключения к
псевдотерминалу (`/dev/pts/XXX`), через который UART-периферия
симулируемого чипа обменивается данными с хост-системой.

Когда Verilator запускает симуляцию OpenTitan, DPI-модуль `uartdpi`
создаёт псевдотерминал и выводит его путь в stdout:

```
UART: Created /dev/pts/4 for uart0. Connect to it with any terminal program, e.g.
$ screen /dev/pts/4
```

Этот псевдотерминал — виртуальный последовательный порт. С одной стороны
к нему подключён процесс Verilator (через master-дескриптор PTY), с
другой — пользователь через `screen` (через slave-устройство
`/dev/pts/XXX`). Всё, что пользователь набирает в `screen`, попадает
в RX FIFO UART-периферии внутри симуляции, а всё, что прошивка Zephyr
выводит через `uart_poll_out()`, появляется на экране `screen`.

---

## Подключение

После запуска симуляции Verilator, в выводе появится строка с номером
созданного псевдотерминала. Для подключения к нему необходимо открыть
**отдельный терминал** и выполнить:

```bash
screen /dev/pts/XXX
```

где `XXX` — номер, указанный в выводе Verilator.

При подключении к реальному последовательному порту обычно указывают
baud rate (например, `screen /dev/ttyUSB0 115200`), однако для
псевдотерминала это не требуется: PTY передаёт данные напрямую через
ядро Linux без физической сериализации, поэтому параметры baud rate,
чётности и стоп-битов не влияют на передачу.

---

## Управление сессией

Все управляющие команды `screen` начинаются с комбинации `Ctrl+A`,
после которой нажимается клавиша действия:

- `Ctrl+A`, затем `K` — завершить сессию (kill window), `screen`
  запросит подтверждение `y/n`
- `Ctrl+A`, затем `\` — завершить `screen` полностью, закрыв все окна
- `Ctrl+A`, затем `D` — отсоединиться от сессии (detach), при этом
  сессия продолжает работать в фоне и к ней можно вернуться командой
  `screen -r`

Важно: обычная комбинация `Ctrl+C` внутри `screen` **не завершает**
сам `screen` — она отправляет сигнал `SIGINT` в подключённое устройство
(то есть в симуляцию через PTY). Для выхода из `screen` используйте
только команды выше.

## Зачем нужен screen, если есть uart0.log?

Данные, выведенные прошивкой через UART, записываются одновременно
в два места: в псевдотерминал (`/dev/pts/XXX`) и в лог-файл
(`uart0.log`). Разница между ними:

- **screen + /dev/pts/XXX** — двусторонний канал. Позволяет не только
  видеть вывод, но и отправлять данные в прошивку (вводить символы с
  клавиатуры). Данные отображаются в реальном времени, так как запись
  в PTY использует прямой системный вызов `write()` без буферизации.

- **uart0.log** — односторонний канал, только запись. Содержит весь
  UART-вывод, но по умолчанию данные появляются в файле только после
  завершения Verilator из-за буферизации `fwrite()` (см.
  [Патч верилятора](Патч_верилятора.md)). Ввод данных в прошивку через
  лог-файл невозможен.

Таким образом, `screen` — удобный способ интерактивного
взаимодействия с прошивкой, работающей внутри симуляции.

Пример программы, которая выполняется в Zephyr и обрабатывает
входящие с uart-сигналы представлена в [uart_msg.c](source/uart_msg.c).
